Greedy regret heuristics report

Paweł Charkiewicz 160288, Piotr Franc 160306

Objective = cycle length (Euclidean, rounded to nearest integer) + sum of selected node costs. Lower is better.

Pseudocode

All methods read the instance into masterArray, which stores every node (x, y, cost). M = number of runs (one per row; for the heuristics, row m starts from node m), N = solution size = ⌈n/2⌉, d(a, b) = Euclidean distance rounded to the nearest integer. For the regret-based methods, best1(k) and best2(k) are the smallest and the second smallest insertion cost of node k over all allowed positions, and regret(k) = best2(k) − best1(k) (0 when only one position exists).

Nearest neighbor (any position) + 2-regret

0. Compute an n × n distance matrix d between every pair of nodes.
1. Initialise M lists of length N.
2. For every row m:
3.     Put node m at position 0.
4.     While row m holds fewer than N nodes:
5.         For every unused node k, compute the insertion cost at every position on the open path:
               before the first node:          d(k, first) + cost(k)
               between neighbours a and b:     d(a, k) + d(k, b) − d(a, b) + cost(k)
               after the last node:            d(last, k) + cost(k)
           Take the smallest value best1(k), the second smallest best2(k), and the position pos(k)
           that gives best1(k). regret(k) = best2(k) − best1(k).
6.         Choose the node k with the greatest regret (ties: smaller best1) and insert it at pos(k).
           Mark it as used.
7. Repeat until every list holds N nodes.

Greedy cycle + 2-regret

0. Compute an n × n distance matrix d between every pair of nodes.
1. Initialise M lists of length N.
2. For every row m:
3.     Put node m at position 0.
4.     While row m holds fewer than N nodes:
5.         For every unused node k, compute the insertion cost for every edge (a, b) of the
           cycle, including the closing edge:
               d(a, k) + d(k, b) − d(a, b) + cost(k)
           Take the smallest value best1(k), the second smallest best2(k), and the edge pos(k)
           that gives best1(k). regret(k) = best2(k) − best1(k).
6.         Choose the node k with the greatest regret (ties: smaller best1) and insert it into
           the edge pos(k). Mark it as used.
7. Repeat until every list holds N nodes.

Nearest neighbor (any position) + weighted sum

0. Compute an n × n distance matrix d between every pair of nodes.
1. Initialise M lists of length N.
2. For every row m:
3.     Put node m at position 0.
4.     While row m holds fewer than N nodes:
5.         For every unused node k, compute best1(k), best2(k), regret(k) and pos(k) exactly as in
           the 2-regret variant, over all positions on the open path (start, between, end).
6.         Compute the weighted criterion:
               score(k) = w1 · regret(k) − w2 · best1(k),    w1 = w2 = 1
           (the regret is rewarded, the immediate cost of the best insertion is penalised).
7.         Choose the node k with the greatest score and insert it at pos(k). Mark it as used.
8. Repeat until every list holds N nodes.

Greedy cycle + weighted sum

0. Compute an n × n distance matrix d between every pair of nodes.
1. Initialise M lists of length N.
2. For every row m:
3.     Put node m at position 0.
4.     While row m holds fewer than N nodes:
5.         For every unused node k, compute best1(k), best2(k), regret(k) and pos(k) exactly as in
           the 2-regret variant, over every edge of the cycle (including the closing edge).
6.         Compute the weighted criterion:
               score(k) = w1 · regret(k) − w2 · best1(k),    w1 = w2 = 1
           (the regret is rewarded, the immediate cost of the best insertion is penalised).
7.         Choose the node k with the greatest score and insert it into the edge pos(k).
           Mark it as used.
8. Repeat until every list holds N nodes.

Exploration of weights

In the weighted sum, the node with the greatest score(k) = w1 · regret(k) − w2 · best1(k) is inserted. The ratio w1 : w2 sets the trade-off between the regret (how much the node loses by waiting) and the immediate cost of its best insertion; w2 = 0 gives pure 2-regret.

We tested five ratios (1:0.5, 1:0.67, 1:1, 1:1.5 and 1:2) for both base methods on both instances. Every setting was run from each of the 200 starting nodes; the tables show the minimum, average and maximum objective (the lowest average of each method is in bold).

Giving too little weight to the insertion cost (1:0.5) is usually the worst choice, which confirms that the regret alone is not enough. The best results lie between 1:1 and 1:2. The lowest average is reached for 1:1.5 in three of the four cases, and in the remaining one (Greedy cycle on TSPA) 1:2 is only 0.1% better. The ratio matters most on TSPB, where 1:1.5 improves the average by 3.6–4.0% over 1:1, while on TSPA the differences between 1:1 and 1:2 stay below 1%. The best minimum falls on a different ratio in every case, so the averages are the more reliable basis for choosing the weights.

Conclusions

When testing the weights for weighted sum it turned out that the 1:1 ratio was the best.

Across both instances, the heuristics with a built-in cost-aware criterion win. Greedy cycle with the weighted sum is best on TSPA, and nearest neighbor (any position) with the weighted sum is best on TSPB. Plain greedy cycle and nearest neighbor with insertion at any position come within a few percent of the best on both.

The ranking is not identical across instances. On TSPA the greedy cycle variants lead. On TSPB the nearest neighbor variants are stronger and less stable. So no single method dominates, but the regret is a reliable heuristic.
