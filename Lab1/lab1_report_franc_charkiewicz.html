Greedy heurestics report

Objective = cycle length (Euclidean, rounded to nearest integer) + sum of selected node costs. Lower is better.

Pseudocode

All methods read the instance into masterArray, which stores every node (x, y, cost). M = number of runs (one per row; for the heuristics, row m starts from node m), N = solution size = ⌈n/2⌉, d(a, b) = Euclidean distance rounded to the nearest integer.

Random

1. Initialise an M × N array.
2. For every row m:
3.     For every position n: put a random node index that is not yet used in row m.
4. Repeat until the entire array is filled.

Nearest neighbor (end)

1. Initialise M lists of length N.
2. For every row m:
3.     Put node m at position 0.
4.     For every position n from 1 to N − 1:
5.         Among unused nodes, find h minimising the cost of appending it to the end of the path:
               d(last, h) + cost(h), where last is the node at position n − 1.
6.         Append h and mark it as used.
7. Repeat until every list holds N nodes.

Nearest neighbor (any position)

0. Compute an n × n distance matrix d between every pair of nodes.
1. Initialise M lists of length N.
2. For every row m:
3.     Put node m at position 0.
4.     While row m holds fewer than N nodes:
5.         Among unused nodes k and all positions on the open path, find the one with the minimal
           immediate cost of insertion:
               before the first node:          d(k, first) + cost(k)
               between neighbours a and b:     d(a, k) + d(k, b) − d(a, b) + cost(k)
               after the last node:            d(last, k) + cost(k)
           (the edge closing the cycle, last → first, is not considered)
6.         Insert k at that position and mark it as used.
7. Repeat until every list holds N nodes.

Greedy cycle

0. Compute an n × n distance matrix d between every pair of nodes.
1. Initialise M lists of length N.
2. For every row m:
3.     Put node m at position 0.
4.     While row m holds fewer than N nodes:
5.         The nodes in row m form a Hamiltonian cycle (the last node links back to the first).
           Among unused nodes k and every edge (a, b) of the cycle, including the closing edge,
           find the one with the smallest increase in cost:
               d(a, k) + d(k, b) − d(a, b) + cost(k)
6.         Insert k between a and b and mark it as used.
7. Repeat until every list holds N nodes.

Conclusions

Among the four tested methods, random search unsurprisingly performs the worst. Nodes are linked erratically, without exploiting any locality, which results in long and inefficient connections.

Nearest neighbour (end) cuts the average cost by more than half compared to random search. It exploits the locality of neighbouring nodes, but it is clearly limited by always attaching the next node to the end of the current path.

Nearest neighbour (any position) performs better still, lowering the average cost by over ten thousand compared to nearest neighbour (end). Exploiting locality along the entire path lets each new node be placed where it fits best.

Greedy cycle performs the best on average and in the worst case, slightly ahead of nearest neighbour (any position), although the latter found the single best solution. Greedy cycle applies the heuristic to the entire tour at every step, including the edge between its ends, so the solution is built with the final cycle in mind from the start. This is significant, because nearest neighbour (any position) only joins the ends of the path at the very end, while greedy cycle keeps optimising with that closing edge accounted for.
